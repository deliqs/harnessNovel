HarnessNovel CLI input/output map

Break the current automated novel-writing workflow into commands, phases, inputs, outputs, and downstream uses, focusing on how file assets pass from step to step.

CLI command / processing step Input Intermediate assets Output Workflow risks
Global path rule: The workspace is determined by the current directory when you run a command, for example <current-dir>/my-novels/<novel-name>。 A common example path is /Users/xiongtao/Documents/my-novels/my-novel。

Command input/output details

novel init my-novel --txt reference-novel.txt Create the project, deconstruct the reference novel, and extract the book outline, volume outlines, and story arcs ›
Input
  • --txt /path/to/reference-novel.txt
  • --batch-size，default about 20 chapters per batch summary
Internal steps
  • Create my-novels/my-novel, reference, file_system
  • Copy the reference novel to reference/sample_novel.txt
  • Split chapters into reference/chapters
  • Extract reference story arcs and volume outlines into reference/outlines
  • If there is only one volume, try an intelligent volume split
Output
  • reference/sample_novel.txt
  • reference/chapters/vol_xx_xxx/chapter_001.md
  • reference/chapters/_volumes.json
  • reference/outlines/novel_outline.md
  • reference/outlines/vol_xx_xxx/volume_outline.md
  • reference/outlines/vol_xx_xxx/story_arcs/arc_xxx.md
Downstream
  • reference/outlines Used by new-book design, stage design, and story-arc generation
novel world-import my-novel source-paths... Import target-world sources; multiple files or directories are allowed ›
Input
  • /path/to/primary-source.txt
  • /path/to/setting-notes/，directories are imported recursively
  • --force can overwrite existing imports
Internal steps
  • Detect whether each path is a file or a directory
  • Source files inside a directory are collected in bulk
  • Write into the import area and record them in the manifest
Output
  • file_system/world_knowledge/imports/
  • file_system/world_knowledge/imports/manifest.json
Downstream
  • world-build Reads imports and the manifest, then structures target-world knowledge
novel world-build my-novel Structure target-world sources into a world knowledge base ›
Input
  • file_system/world_knowledge/imports/manifest.json
  • file_system/world_knowledge/imports/*
  • --chunk-size，chunk size when there is no chapter structure
  • --chapter-batch-size，chapters per batch when slicing by chapter
  • --max-workers，legacy parameter; the current all-section aggregation mode usually does not need it
  • --primary，set the primary source as file name, path, or source ID
  • --merge-only，rebuild worlds/_final/ and audits from existing worlds/<source-name>/*.md only
Internal steps
  • If --primary is set, that source is the primary source
  • If --primary is omitted, the largest file is the primary source
  • Other sources are supplement sources: they do not change the mainline, but can correct/enrich the power system, skill system, artifacts, character power background, and worldview details
  • Prefer chapter slices, about 20 chapters per batch
  • If chapters cannot be detected, slice by character length
  • Extract primary-source cards first and generate canon_index.md as the shared canon baseline
  • Supplement-source card extraction reads canon_index.md and separates shared supplements, sample-original content, and uncertain content
  • Extract 7 section types per chunk: worldview, power system, key characters, factions, main plot, key items, skill system
  • Each source is aggregated serially as “2 new cards + previous all-section summary”, writing 7 sections at once
  • Split the all-section summary into section files such as worlds/<source-name>/世界观.md
  • Merge supplement sources into worlds/_final/ with “mainline stays with the primary source; setting details follow information quality”
  • Write audits/supplement_usage_audit.md to check whether supplement sources were over-filtered or underused for correction
Output
  • file_system/world_knowledge/canon_index.md
  • file_system/world_knowledge/cards/
  • file_system/world_knowledge/partials/<source-name>/_all_sections/partial_001.md
  • file_system/world_knowledge/worlds/<source-name>/世界观.md
  • file_system/world_knowledge/worlds/<source-name>/力量体系.md
  • file_system/world_knowledge/worlds/_final/世界观.md
  • file_system/world_knowledge/worlds/_final/力量体系.md
  • file_system/world_knowledge/partials/_final/_all_sections/integrated_001_xxx.md
  • file_system/world_knowledge/audits/supplement_usage_audit.md
Downstream
  • novel-outline uses it to check and correct the first new-book design
  • If it is built after novel-outline, rerun novel novel-outline --force
novel novel-outline my-novel --direction "inspiration" Generate core gameplay, long mainline, stage roadmap, and character arcs ›
Input
  • --direction, --direction-file, or creative_direction.md
  • reference/outlines
  • file_system/world_knowledge/worlds/_final/*.md, if present
Internal steps
  • Generate core gameplay from the reference gameplay loop and user inspiration
  • Generate a standalone book-length long mainline around core gameplay
  • Generate the book stage roadmap with stages as the top-level units
  • Generate character arcs from core gameplay, long mainline, and the stage roadmap
  • If a target-world knowledge base exists, check target-world consistency; otherwise skip this step automatically
  • Automatically generate title and synopsis
Output
  • file_system/story_design/core_gameplay.md
  • file_system/story_design/long_mainline.md
  • file_system/story_design/stage_roadmap.md
  • file_system/story_design/character_arcs.md
  • file_system/novel_name_synopsis.md
Downstream
  • stage-insert can insert a new stage from inspiration and update the stage roadmap
  • mechanics-init can initialize the optional mechanics layer from core gameplay
  • story-arcs reads the matching volume/stage and generates story arcs
  • write reads story arcs, chapter outlines, and stage context
novel mechanics-init my-novel --file mechanics.md Initialize the optional mechanics layer ›
Input
  • --file mechanics settings file, highest priority
  • --direction or --direction-file mechanics direction
  • file_system/story_design/core_gameplay.md
  • file_system/story_design/long_mainline.md
  • file_system/story_design/stage_roadmap.md
  • file_system/story_design/character_arcs.md
Internal steps
  • Decide the mechanics mode: none、light_state、explicit_mechanics
  • Honor user mechanics settings when provided; otherwise auto-detect from core gameplay
  • Generate rules, initial state, and display bounds
  • --none can explicitly disable the mechanics layer
Output
  • file_system/mechanics/profile.json
  • file_system/mechanics/design.md
  • file_system/mechanics/rules.json
  • file_system/mechanics/state.json
Downstream
  • story-arcs reads mechanics bounds into arc_context
  • chapter-outlines can output mechanics event drafts, but does not compute numbers itself
  • write reads mechanics state and rules; ignored automatically when disabled
novel volume-outline my-novel Generate a new volume outline and volume worldview for each volume ›
Input
  • file_system/novel_outline.md
  • file_system/new_novel_worldview.md
  • file_system/adaptation/rewrite_map.md
  • reference/outlines/vol_xx_xxx
  • --volume can target a single volume
  • --direction can add direction for this volume outline
Internal steps
  • Read reference volume structure and the new-book master design
  • If the mapping table is missing, try to generate it automatically
  • Generate a new outline for one volume
  • Generate a volume worldview from that volume outline
  • Aggregate all volume outlines
Output
  • file_system/new_volume_outlines/vol_01_outline.md
  • file_system/new_worldviews/vol_01_worldview.md
  • file_system/volume_outline.md
Downstream
  • story-arcs uses this volume outline and worldview to generate story arcs
  • chapter-outlines generates chapter outlines from story arcs
  • write constrains draft with this volume outline and worldview
novel story-arcs my-novel --volume 1 Generate new-novel story arcs ›
Input
  • file_system/story_design/core_gameplay.md
  • file_system/story_design/long_mainline.md
  • file_system/story_design/stage_roadmap.md matching volume/stage
  • file_system/story_design/character_arcs.md
  • file_system/mechanics，if initialized
  • reference/outlines/vol_xx_xxx/story_arcs/arc_xxx.md
  • Older workspaces can fall back to reference/outlines/vol_xx_xxx/batch_xxx.md
  • This step does not read reference/chapters draft text
Multi-step flow
  • Infer this stage's chapter count from Planned chapters on the current stage
  • Plan new-novel story arcs at about 5 chapters per arc by default
  • Generate or reuse the current-stage arc_context, compressing gameplay, mainline, stage, character, and mechanics constraints
  • By default pick one reference story arc as the narrative sample and abstract it into story_pattern
  • Generate new-novel story arcs from arc_context + story_pattern + previous new-book arcs
  • Write the story-arc index for chapter-outline and draft steps
Output
  • file_system/adaptation/arc_contexts/vol_xx_context.md
  • file_system/adaptation/story_patterns/vol_xx/arc_xxx.md
  • file_system/story_arcs/vol_xx/arc_xxx_ch001_005.md
  • file_system/story_arcs/vol_xx/arcs_index.json
Meaning
  • Reference chapter ranges in logs mean “narrative-pattern source”, not a 1:1 map from new-book chapters to reference chapters
  • story_pattern keeps only plot function, conflict structure, emotional pacing, payoff mechanics, and hook method
  • In the current flow one volume is one stage; --stage is only a compatibility alias for --volume, not a stage inside a volume
Downstream
  • file_system/story_arcs as the plot blueprint for chapter outlines
  • file_system/story_arcs also as plot background for draft generation
novel chapter-outlines my-novel --volume 1 Generate chapter outlines from story arcs ›
Input
  • file_system/story_arcs/vol_xx/arc_xxx.md
  • file_system/story_design/stage_roadmap.md matching volume/stage
  • file_system/mechanics，if initialized
  • the previous two chapter outlines, if they exist
Internal steps
  • Read generated story arcs
  • Read the mechanics layer; when enabled, outlines may output mechanics event drafts but do not compute final numbers
  • Generate chapter outlines one chapter at a time across each story arc's chapter range
  • Each chapter reads the previous two chapter outlines for local continuity
  • If story arcs are missing, it prompts you to run story-arcs first
Output
  • file_system/chapter_outlines as the direct blueprint for draft generation
novel write my-novel --volume 1 Generate draft from chapter outlines ›
Input
  • file_system/chapter_outlines/vol_xx/chapter_NNN.md
  • file_system/story_arcs/vol_xx/arc_xxx.md
  • file_system/story_design/stage_roadmap.md matching volume/stage
  • file_system/story_design/long_mainline.md
  • file_system/mechanics，if initialized
  • Older workspaces can fall back to file_system/outlines/vol_xx/batch_XXX_YYY.md
  • Older workspaces can fall back to file_system/new_volume_outlines/vol_xx_outline.md and file_system/new_worldviews/vol_xx_worldview.md
  • Older workspaces may optionally read file_system/adaptation/rewrite_map.md
  • reference/chapters proportionally matched reference chapters
  • the previous two draft chapters, if they exist
  • core/system_prompt.md and core/agents.md
Internal steps
  • Decide the chapter range to generate, supporting --start and --max
  • Read chapter outlines, story arcs, the current stage, mainline bounds, and mechanics constraints
  • Read matching reference chapters as pacing and prose samples
  • Call the draft-generation model
  • Write chapter draft text
Output
  • file_system/chapters/vol_xx/001_chapter_1.md
  • file_system/chapters/vol_xx/002_chapter_2.md
Watch-outs
  • The draft step still reads reference chapter text as a prose sample, so chapter outlines and current-stage constraints must prevent copying
  • Static leftover-keyword scanning is off; if auditing returns later, it should be plot-consistency auditing
novel novel-name-synopsis my-novel Generate or regenerate title and synopsis ›
Input
  • file_system/story_design/core_gameplay.md
  • file_system/story_design/long_mainline.md
  • file_system/story_design/stage_roadmap.md
  • file_system/story_design/character_arcs.md
  • creative_direction.md
Internal steps
  • Generate title, synopsis, and selling points from core gameplay, long mainline, stage roadmap, character arcs, and inspiration
  • novel-outline currently triggers this capability once automatically
Output
  • file_system/novel_name_synopsis.md

Key asset chains

Reference-novel chain

sample_novel.txt → reference/chapters + reference/outlines → new-book structure, story-arc pacing, and draft pacing.

Target-world chain

Optional enhancement chain: world-import → world-build → worlds/_final/*.md → consistency checks for core gameplay, long mainline, stage roadmap, and character arcs. Without this chain, novel-outline degrades automatically.

Stage-design chain

core_gameplay.md → long_mainline.md → stage_roadmap.md + character_arcs.md → story arcs.

Narrative-pattern chain

reference story arcs + arc_context → story_pattern → new story arc。Reference arcs only provide structural function and emotional pacing.

Mechanics-layer chain

Optional chain: mechanics-init → mechanics/profile.json + rules.json + state.json → state constraints for arcs, chapter outlines, and draft.

Draft-generation chain

story arc → chapter outline → chapter text，Draft still consults original chapter text.

Current workflow risks

The target-world knowledge base is an optional enhancement. If world-build runs after novel-outline, those sources are not injected into an existing outline; rerun novel novel-outline --force.
novel-outline generates core gameplay first, then long mainline, stage roadmap, and character arcs. If core gameplay is off, later stages and arcs follow it.
story-arcs and chapter-outlines are separate; rerunning story arcs affects later outlines and must be regenerated in order.
The write step still reads reference draft. If prompt constraints are weak, old-world details can leak back into the draft.
